# Construction OS — Content Security Policy

> **Purpose:** Define the Content-Security-Policy (CSP) header for all HTTP responses.
> Source: QM-4. CSP is enforced via NestJS `helmet()` middleware in
> `backend/src/shared/middleware/security-headers.middleware.ts` and
> Next.js `next.config.js` custom headers.
>
> **Hard constraints (QM-4):**
>
> - `unsafe-inline` is **forbidden** in production
> - `unsafe-eval` is **forbidden** in production
> - Nonce-based script allowlisting must be used for any inline script requirements

---

## Production CSP

Applied to all `*.construction-os.app` origins in production.

```
Content-Security-Policy:
  default-src 'self';
  script-src 'self' 'nonce-{NONCE}';
  style-src 'self' 'nonce-{NONCE}';
  img-src 'self' data: blob: https://cos-files-production.s3.ap-southeast-1.amazonaws.com https://cos-files-production.s3.amazonaws.com;
  font-src 'self' data:;
  connect-src 'self'
    https://api.construction-os.app
    https://cos-files-production.s3.ap-southeast-1.amazonaws.com
    wss://api.construction-os.app
    https://o0.ingest.sentry.io;
  media-src 'self' blob: https://cos-files-production.s3.ap-southeast-1.amazonaws.com;
  object-src 'none';
  frame-src 'none';
  frame-ancestors 'none';
  base-uri 'self';
  form-action 'self';
  upgrade-insecure-requests;
  block-all-mixed-content;
```

### Nonce generation

A per-request nonce is generated by the NestJS middleware and injected into:

- The `Content-Security-Policy` header (replacing `{NONCE}`)
- The Next.js `_document.tsx` via `res.locals.cspNonce`

Nonce format: `crypto.randomBytes(16).toString('base64')` — 128 bits of randomness.

---

## Staging CSP

Same as production. **Do not use** `unsafe-inline` or `unsafe-eval` in staging — violations
there indicate a production risk.

---

## Development CSP (local only)

```
Content-Security-Policy-Report-Only:
  default-src 'self';
  script-src 'self' 'unsafe-inline' 'unsafe-eval';
  ...
```

Development uses `Report-Only` mode so violations are logged but not enforced.
`unsafe-inline` and `unsafe-eval` are allowed in development only (Next.js HMR requires them).

## Allowed external origins (justification)

| Directive     | Origin                                                | Justification                                  |
| ------------- | ----------------------------------------------------- | ---------------------------------------------- |
| `img-src`     | `https://cos-files-*.s3.ap-southeast-1.amazonaws.com` | S3 presigned URLs for project photos           |
| `connect-src` | `wss://api.construction-os.app`                       | SSE / WebSocket for real-time notifications    |
| `connect-src` | `https://o0.ingest.sentry.io`                         | Error reporting (if Sentry added in Stage 2+)  |
| `media-src`   | `blob:`                                               | Photo preview from camera capture (mobile web) |

---

## CSP violations

Violations are reported to the backend via `report-uri` / `report-to` directive (Stage 2+).
In Stage 1, violations are logged to the browser console only.

Stage 2 addition:

```
report-to cos-csp-violations;
Report-To: {"group":"cos-csp-violations","max_age":10886400,"endpoints":[{"url":"https://api.construction-os.app/api/v1/security/csp-report"}]}
```

## Other mandatory security headers (QM-4)

Set alongside CSP on every HTTP response:

| Header                      | Value                                          |
| --------------------------- | ---------------------------------------------- |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains`          |
| `X-Content-Type-Options`    | `nosniff`                                      |
| `X-Frame-Options`           | `DENY`                                         |
| `Referrer-Policy`           | `strict-origin-when-cross-origin`              |
| `Permissions-Policy`        | `camera=(), microphone=(), geolocation=(self)` |

These are configured via `helmet()` in `backend/src/main.ts` and
`next.config.js` `headers()` function.
